3.移植自UE的 Gameplay Ability System 游戏能力系统
读完了。先把结论钉死:Endfield 确实是 UE GAS 的逐组件对位移植,这不是像不像的问题,是一一对应。

Endfield = GAS,而且是加强版
UE GAS	Endfield(实测住址)
AbilitySystemComponent	AbilitySystem : TickComponent(81722 行 / 76 类型)
GameplayAbility	Skill + SkillData(castData/cooldownTime/costData/maxChargeTime)
AbilityTask	AbilityAction(ExecutingState{Pending,ExecutedNotStartTick,Ticking,Ended})
GameplayEffect	Buff : IReusableObject, IAttributesModifier, IDamageModifierSource, IHealModifierSource, IPoiseModifierSource…
GE Modifier	AbilitySystem.Modifier(struct,5092 行)
AttributeSet	Attributes(10212 行)
GameplayTagQuery/Container	GameplayTagQuery / GameplayTagList
ExecutionCalculation	CalculationBase / DamageProcessorBase
TargetData	TargetSettings / Selector(Finder→PostProcessor→Validator)
Prediction / Replication	IBattleServerData<T> + ConvertToServer() + serverActionIndex + ServerActionParams
它比 UE GAS 多两样 UE 本身没有的:

双时序内建进数据契约。ActionGroupData 只有两个字段:timelineActions:List<TimelineAction.TimelineActionData>(_startFrame/_endFrame 帧区间)和 passiveEventActions:List<AbilityActionMap>(事件)。UE GAS 只有事件流,时间轴得靠 Montage Notify 外挂。
服务器权威做成了 schema。每个数据类都 IBattleServerData<XXX_RES>,SequenceActionData.SetServerActionIndex(ref int),ServerActionParams 带 BATTLE_TRIGGER_TYPE/BATTLE_ACTION_INST。这是 prediction key 的等价物,但下沉到了数据层。
