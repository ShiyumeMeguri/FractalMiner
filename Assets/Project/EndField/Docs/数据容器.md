# 数据容器

## AB 只占一半

VFS 里 44.9 万个文件，`.ab` 只有 23.8 万（47%）——**cabmap 只索引 .ab，其余完全看不见**。

非 AB 的大头：`Data/Streaming/`（场景）、`Data/Terrain/`、`Data/Json/`（含 LipSync 等）、
`Data/TableCfg/`（693 张配置表）、`Data/DynamicStreaming/`、`Data/LuaScripts/`。

**教训：凡是「查不到某数据」，先问是不是索引层只认一种容器。** 曾因只搜 AB 侧，两次得出
「数据本地不存在」的错误结论。

## 四种格式各管什么

| 格式 | 住哪 | 管什么 |
|---|---|---|
| Unity AssetBundle | `*.ab` | 网格 / 材质 / 贴图 / prefab / 动画 |
| **FlatBuffers** | `Data/Streaming/`、`Data/DynamicStreaming/` | 场景美术摆放，见 [流场景设计.md](流场景设计.md) |
| **TableCfg**（自研，自带 schema） | `Data/TableCfg/*.bytes` | 配置表 |
| **MemoryPack** | `Data/Json/**`（`.json` 是幌子） | 关卡逻辑数据、技能、Buff，见 [关卡逻辑数据.md](关卡逻辑数据.md) |

## TableCfg

自带 schema，所以不需要生成代码。读取实现见 `TableCfgFile.cs`（头注释是权威语法说明）。

**唯一要记的布局规则：每个槽落在满足自身对齐的下一个绝对文件偏移。** 这一条同时解释
struct 填充、list 步长、map entry 步长。`bool` 宽 1 字节。

判定布局对不对最灵敏的探针：**统计行数据段的字节覆盖率**（`bool` 用错宽度会让覆盖率从 100% 掉到 79%）。

常用表：

| 表 | 用途 |
|---|---|
| `MapIdTable` | 开放世界大地图名（map01 / map02 / base01_lv001） |
| `LevelDescTable` | 关卡名，含全部地标 |
| `I18nTextTable_<LANG>` | 本地化文本，14 种语言 |
| `TextTable` | 文本键 → 文本 id |
| `CharacterTable` / `NpcTemplateGroupTable` / `NpcInfoTable` | 角色与 NPC 花名册 |
| `MapMarkInsTable` / `MapMarkTypeTable` | 地图标记，见 [传送点设计.md](传送点设计.md) |
| `SceneAreaTable` | 区域 ↔ 场景，但 areaId 与 chunk 文件名里的整数**对不上** |

名字统一走 `showName.id` 或 `name.id` → `I18nTextTable_<LANG>` 一跳。
