# 流场景设计

## 核心结论

**游戏永远只加载玩家周围一圈格，整图从不在内存里。** 任何「整图导入」都是违背设计的：
map02 整图 = 3387 个 chunk / 270 MB / 48.5 万个摆放 → 2.68 万个闭包 CAB。

## 两大家族

| 家族 | 路径 | 根 schema | 内容 |
|---|---|---|---|
| STREAMING | `Data/Streaming/PC/<map>/Streaming/` | `FBStreamingChunkData` | 静态世界几何 / 道具 / 碰撞（ECS blob） |
| DYNAMICSTREAMING | `Data/DynamicStreaming/PC/Scene/<map>/` | `FBDynamicSceneChunkData` | 网格化摆放的 Model / Effect / Tree |

schema 维护在 `Ruri-RipperHook` 的 `…/StreamingScene/Fbs/*.fbs`，用 flatc 生成绑定。

## 文件名就是坐标

```
InitChunkData_<gx>_<gy>_<sceneStateId>_<areaId>.bytes
StreamingChunkData_<gx>_<gy>_<sceneStateId>_<areaId>.bytes
InitChunkData_Global_<sceneStateId>_<areaId>.bytes    ← 全图级，不锚定格
fb_main_<lod>_<x>_<y>.bytes                           ← 自己的 LOD 网格，不是流式格
fb_init_* / fb_streaming_*                            ← 数字段不是格坐标
StreamingChunkInfo.bytes / FBStreamArea.bytes         ← 头文件，无摆放
```

**`_Global_` 块很贵**：map02 里它单独就占整图闭包 CAB 的三分之二，而且按文件名无法筛，
只能靠「选中格的世界矩形」给它收边。

## 格坐标 ↔ 世界坐标

**`FBStreamingChunkData.chunk_pos` 是该格的世界原点，不是格号。**
所以 **格边长 = chunk_pos / 格号 = 128**，这条可自校验，不用硬编码。

**`FBGridData.grid_bounds` 不是格矩形**，是内容 AABB，而且会被「只有 bounds 中心当变换源」
的实体拖到世界原点（单格能算出 900×1300 的假矩形）。
**绝不能拿它、也不能拿摆放位置当窗口边界。**

另：`MapConfig/<map>.json` 的 `sideGridNum` 是**关卡网格**（map01 16×16、map02 32×32），
和 chunk 格是两回事。

## 游戏自己的加载调用链

```
Beyond.Gameplay.View.BaseGameScene
  → Beyond.Gameplay.Streaming.StreamingUnsafeUtilsV2.CreateStreamingSourceData(
        streamingPos, chunkLoadRadius, 各层 radius…, layerEnabled)
  → UnityEngine.HyperGryph.Streaming.StreamingSceneV2.primaryStreamingSourceData = …
  → StreamingSceneV2.SetArea(areaId, bool) / SetSceneState(id, bool)
  → StreamingSceneV2.UpdateNeedProcessChunkGridSet()
```

- 半径参数在 `HG.RenderPipelines.Runtime.StreamingSettingParameters`（feature `"Streaming"`）
- `StreamingLayer`：Default / Persistent / HLOD0-2 / Collider / Tiny / Water / Lighting / Audio / RendererWithCollider
- 格索引数学：`StreamingSceneUtils.GetChunkIndexFromPos(Vector2)` / `GetChunkRectFromIndex`
- **窗口天然是世界坐标**（位置 + 半径），不是格号

## 摆放的变换来源（三级）

按优先级：

1. ECS blob 的 `LocalToWorld` —— 权威变换
2. 校验过的 `FBPropertyBytesData` 位姿（位置 + 四元数；载荷无缩放 ⇒ 缩放取 1）
3. `FBPropertyBoundsData.Center` —— 仅位置

**第 3 级不可省**：大型静态建筑（地板 / 墙 / 地形块）常常前两级都没有，漏掉等于静默删掉可见几何。
三者皆无 ⇒ 标记为无变换、**排除而不是摆在原点**。

材质：同一个 `FBPropertyAssetData` 列表里 `AssetType==2` 是网格、**`AssetType==1` 是材质**，
走同一张 `StringPathHash` 表，不需要命名约定猜测。
