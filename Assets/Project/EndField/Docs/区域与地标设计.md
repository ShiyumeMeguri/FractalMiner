# 区域与地标设计

## 两类场景（判据是游戏自己给的）

`Data/Json/UILevelMapLoadConfig/LoadListConfig.json` 的 `loadLevelList` 列出地图 UI 能显示的
level，各自 `<levelId>.json` 的 **`basic.isSingleLevel`**：

- `true` ⇒ **箱庭**：自成一关的地牢 / 站内场景，小到可以整个加载
- `false` ⇒ **大地图里的地标**，归属于「id 是它前缀的那个场景」

据此，全部流式场景里**流场景恰好只有 map01 / map02**，其余 81 个是箱庭。
**不要按名字猜。**

## 地标的世界矩形 = 游戏对「多大」的判定

同一个 `<levelId>.json` 的 `basic.worldRectLeftBottom` / `worldRectRightTop`（`Vector2`，
**y 就是世界 Z**；`needInverseXZ` 只有 base01 那两个箱庭为 true）。

**矩形天然对齐 128 的 chunk 格。** 例：供能高地 `map01_lv007` = x[-640..384] z[-128..896]，正好 8×8 格。

地标尺寸大致 640×640 ~ 1408×1024，对应的依赖闭包在 3000 ~ 10000 个 CAB 量级——
换算内存见 [Blender加载管线.md](Blender加载管线.md)，**最小的地标在 32 GB 机器上也已经接近上限**。

相关类型：`UILevelMapLoadConfig` / `BasicLoadConfigInfo` / `ChunkLoadConfigInfo` /
`GridLoadConfigInfo`（都在 `Beyond.Gameplay`），另有 `MapManager.LoaderLevelData`。

## 名字来源

| 表 | 覆盖 |
|---|---|
| `MapIdTable` | 开放世界大地图：map01 = 四号谷地、map02 = 武陵、base01_lv001 = 塔卫二 |
| `LevelDescTable` | 关卡名，含全部地标（如 map01_lv007 = 供能高地） |

两张表的名字字段都是 `showName.id` → `I18nTextTable_<LANG>`。
流式场景里大部分有名字，少数游戏本身就没给（保留 id 当标签即可）。

## 坑

`SceneAreaTable` 的 `areaId` 是字符串（如 `areaId702` / `region_map02_lv001`），
**和 chunk 文件名里的 areaId 整数对不上**——crc32 / fnv1a / fnv1 / djb2 及掩码变体全试过，
零命中。别再试。
