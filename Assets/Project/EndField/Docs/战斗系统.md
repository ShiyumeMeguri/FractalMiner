# 战斗系统 = UE GAS 的逐组件移植

结论钉死：**不是像不像的问题，是一一对应。**
并且非常的屎山 最大的 AbilitySystem 高达2mb+ 除非是 partial 类 不然太恐怖了

| UE GAS | Endfield |
|---|---|
| AbilitySystemComponent | `AbilitySystem : TickComponent` |
| GameplayAbility | `Skill` + `SkillData`（castData / cooldownTime / costData / maxChargeTime） |
| AbilityTask | `AbilityAction`（`ExecutingState{Pending, ExecutedNotStartTick, Ticking, Ended}`） |
| GameplayEffect | `Buff : IReusableObject, IAttributesModifier, IDamageModifierSource, IHealModifierSource, IPoiseModifierSource…` |
| GE Modifier | `AbilitySystem.Modifier`（struct） |
| AttributeSet | `Attributes` |
| GameplayTagQuery / Container | `GameplayTagQuery` / `GameplayTagList` |
| ExecutionCalculation | `CalculationBase` / `DamageProcessorBase` |
| TargetData | `TargetSettings` / `Selector`（Finder → PostProcessor → Validator） |
| Prediction / Replication | `IBattleServerData<T>` + `ConvertToServer()` + `serverActionIndex` + `ServerActionParams` |

## 比 UE GAS 多的两样

**1. 双时序内建进数据契约。** `ActionGroupData` 只有两个字段：

- `timelineActions: List<TimelineAction.TimelineActionData>` —— 带 `_startFrame` / `_endFrame` 帧区间
- `passiveEventActions: List<AbilityActionMap>` —— 事件

UE GAS 只有事件流，时间轴得靠 Montage Notify 外挂。

**2. 服务器权威做成了 schema。** 每个数据类都 `IBattleServerData<XXX_RES>`，
`SequenceActionData.SetServerActionIndex(ref int)`，`ServerActionParams` 带
`BATTLE_TRIGGER_TYPE` / `BATTLE_ACTION_INST`。相当于 prediction key，但**下沉到了数据层**。

## 数据住哪

技能 / Buff 的数据在 VFS 的 `Data/Json/SkillData/`、`Data/Json/BuffData/`，
是 MemoryPack 二进制（`.json` 只是扩展名）。见 [关卡逻辑数据.md](关卡逻辑数据.md)。
