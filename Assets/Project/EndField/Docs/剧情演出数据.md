# 剧情演出数据（Cutscene / Dialog）

游戏播剧情只有两条通路，都是 Unity Timeline 之上的自研壳：**Cutscene（过场演出）**
与 **Dialog Timeline（对话演出）**。两者共用基类 `CinematicData`
（`Gameplay.Beyond/Beyond/Gameplay/CinematicData.cs`），子类只有
`CutsceneData` 与 `DialogTimelineData` 两个。

## 数据结构

`CinematicData` 里跟动画有关的三个字段：

| 字段 | 内容 |
|---|---|
| `cutsceneName` / `path` | 这场演出的 id 与资源路径 |
| `actors: List<CutsceneActorData>` | 每个演员一条：`CutsceneObjectDescriptor` + 附加组件 + 材质覆写 |
| `animClipData: Dictionary<string, TimelineAnimClipData>` | **clipName → `animationFbxPath` + `AnimationClipAsyncInfo`（长度/帧率/平均速度/isHumanoid/isLooping）** |

演员种类是 `CutsceneEnums.CutsceneObjectType`：Default / Character / Npc / Effect /
AttachObject / Interactive / Decoration / SlotEntity。

轨道种类是 `CutsceneEnums.TrackType`：None / Animation / Activation / Control / Subtitle /
Cinemachine / CommonMask / **BeyondAnimation** / Subsequence / BigLogo / EntityVFXPlayable /
LeftSubtitle / **DialogTrunk / DialogSkeletalMorph / DialogLipSync** / DialogMuteAutoBlink /
DialogAudioEntityBindable —— 对话那半截的表情、口型、静音眨眼各占一条独立轨。

播放入口：`CutsceneManager`（继承 `MainStreamTimelineManagerBase`）、`DialogTimelineManager`。
关卡逻辑用 `PlayCutsceneAction` / `PreloadCutsceneAction` / `StartCutsceneAndTeleportAction`
等 MemoryPack action 触发（见 [关卡逻辑数据.md](关卡逻辑数据.md)）。

## 怎么找到一场演出的数据（加载链路）

`CutsceneManager.CheckCanPlay(key)` → `NarrativeUtils.GetGenderedCutsceneId(key, gender)`
（`f_`/`m_` 前缀就是在这一步拼的）→ `CinematicTimelineManagerBase.TryGetCinematicData<CutsceneData>(id)`。
数据目录来自虚方法 `GetCinematicDataPath()` = `Assets/Beyond/DynamicAssets/Gameplay/Cutscene`
（`DialogTimelineManager` 覆写成 `.../Dialog/Timeline`），**按 key 拼路径取，没有全局注册表**。

同一个 manager 还用 `SimpleAssetLoader.TryLoad<I18NSingleCutsceneSubtitleConfig>(
"…/GameData/Subtitle/Cutscene/SingleConfigs/" + cutsceneName + ".asset")` 取字幕配置——
**这是 ScriptableObject**，另有全局的 `I18NCutsceneSubtitleConfig.cutsceneId2Config`
（`SerializeReferenceDictionary<string, I18NSubtitleAudioBean>`，以 cutscene id 为键）和
`CGConfig.data`（CG 一份）。`DataConst` 里还登记了 `TimelineConfig` / `CGConfig` 这类配置名。

## 磁盘布局（实测 1.4.4，cabmap 242,222 CAB）

**没有任何配置表登记演出。** 693 张 TableCfg 全扫过 `e11m4` / `cutscene` 这类 id，只有
`I18nTextTable_*` / `TextTable` / `NumIdStrTable` / `StrIdNumTable` 这些文本与 id 池命中；
`ChapterMissionChapterTable`、`MissionSelectChapterTable`、`SkipChapterTable` 全都 0 命中。
**演出的真源就是它自己的目录**，id 只在路径里。

演出配置 json 也不在 VFS 的 JsonData 块里（92,000 个 JsonData 全量枚举，`cutscene`
只命中 1 个无关的 NPC prefabinfo），而是作为 TextAsset 打在 AB 里。

`dynamicassets/gameplay/cutscene/` 一共 5,924 行，按扩展名 × 类型分：

| 内容 | 数量 | cabmap 里的类型 |
|---|---|---|
| `<id>/<id>.json` | 131 | **TextAsset** —— 序列化的 `CutsceneData` 本体 |
| `<id>/playable/*.playable` | 5,001 | **MonoBehaviour**，其中 **4,116 个同时带 AnimationClip** |
| `<id>/prefab/*.prefab` | ~790 | GameObject + Transform + PlayableDirector |

🔴 **`.playable` 是 SO（Unity Timeline 的 TimelineAsset/轨道/PlayableAsset 都是
ScriptableObject），而且里面还内嵌 AnimationClip** —— 只按 fbx 目录扫动画会漏掉这一批，
且轨道结构、时间区间、对象绑定全在这些 MonoBehaviour 里，要类型信息才解得出字段。

```
Cutscene
  美术侧  assets/beyond/arts/gameplay/cutscene/<id>/animations/<scNNN>/<leaf>.fbx
  运行侧  assets/gameplay/cutscene/[f_|m_]<id>/<id>.json
                                              /playable/*.playable
                                              /prefab/*.prefab

Dialog
  assets/gameplay/dialog/timeline/[f_|m_]dlgtl_<id>_sub_<n>/<id>.json
                                                           /morphanim/*.anim
                                                           /morphanimso/*.asset
                                                           /playable/ /prefab/
  assets/gameplay/dialog/extraconfig/*.json   （2715 个）
```

- **`<scNNN>` 是分镜**：一场演出按镜头切子目录，`sc001` 起。
- **`f_` / `m_` 前缀 = 主角性别变体**：同一个 id 在运行侧存在两份，美术侧只有一份。
  1.4.4 的 131 个运行侧目录 = 46 个 `m_` + 46 个 `f_` + 38 个无前缀 + 1 个 `fm_`。
- **playable 按轨道族拆文件**：`<id>.playable` / `_actor` / `_audio` / `_effect` / `_light` /
  `_others_au_<lang>`（配音语言各一份）。
- 特效另有一棵树 `assets/beyond/arts/effects/cutscene/<场景>_vfx/`。
- 字幕在 `assets/gamedata/subtitle/cutscene/`（`PathDef.CUTSCENE_SUBTITLE_CONFIG_FOLDER`）。

`PathDef` 里的对应常量：`RUNTIME_CUTSCENE_PATH` = `Assets/Beyond/DynamicAssets/Gameplay/Cutscene`、
`RUNTIME_CUTSCENE_TRANSITION_PATH`、`DYNAMIC_DIALOG_PATH`；**cabmap 的 container 路径会把
`beyond/dynamicassets` 一段吃掉**，所以搜的时候按 `assets/gameplay/cutscene/` 搜。

## 动画文件的命名法

美术侧每个 fbx 都是 `a_<kind>_<subject>_cs_<id>_<scNNN>.fbx`：

| kind | 数量（全库） | 含义 |
|---|---|---|
| `actor` | 1821 | 可操作角色，`subject` 就是角色短名（pelica / chen / yvonne…），主角是 `endminm` / `endminf` |
| `cam` | 640 | 镜头 |
| `item` / `npc` | 491 / 491 | 道具、NPC |
| `monster` | 300 | 怪 |
| `wpn` | 226 | 武器 |
| `cbuild` / `cprop` / `cfoliage` / `crock` / `prop` | ~130 | 建筑 / 陈设 / 植被 / 岩石 |

`subject` 末尾的 `_NN` 是同类编号，不是 LOD。

## Timeline 的形状（实测 `cutscene_e0m2_2` / `cutscene_e0m2_99`）

一场戏是**一主多从**：主 timeline 只有 5 条 `ControlTrack`，各控一个子 timeline，
子 timeline 的文件名就是 `<主>_<控制路径>`（`Actor` / `Audio` / `Effect` / `Light` / `Others`）——
这也是把子 timeline 的时间挂回主时间轴的 join。字幕子 timeline 再按语言分份
（`_Others_AU_CHI` / `_AU_EN` / `_AU_JP` / `_AU_KO` …）。

轨道类（`cutscene_e0m2_2` 的 166 条 clip 分布）：

| 轨道类 | 条数 | 内容 |
|---|---|---|
| `AnimationTrack` | 89 | 演员 44 + **灯光 45**（灯光也是动画轨） |
| `SubtitleTrack` | 32 | `SubtitlePlayableAsset._textId`，如 `cutscene_e0m2_02_01` |
| `ActivationTrack` | 26 | 对象在哪段时间可见 |
| `ControlTrack` | 12 | 子 timeline / 生成 prefab（`prefabGameObject`、`directorControlPath`） |
| `AudioTrack` | 3 | **Wwise/CriWare 事件名**（`au_music_cs_tundra_000_wake_up`、`au_vo_cs_e0m2_2_f`），**没有 AudioClip** |
| `BigLogoTrack` / `CommonMaskTrack` / `EntityVFXPlayableTrack` | 各 1–2 | 大标题、遮罩、实体特效（`asset` 指向 VFX） |

字段就是 Unity Timeline 的原名：`m_Tracks` → `m_Clips`（`m_Start` / `m_Duration` /
`m_ClipIn` / `m_TimeScale` / `m_BlendInDuration` / `m_Muted`）→ `m_Asset` →
`AnimationPlayableAsset.m_Clip`；帧率在 `m_EditorSettings.m_Framerate`（实测 60）。
Beyond 自己加的三个字符串字段很关键：`autoBindingPath`（轨道自绑路径）、
`directorControlPath`（控制哪个子 timeline）、`_textId`（字幕行）。

🔴 **三个会把人坑掉的实测判据**：

1. **ACL 解码出来的采样率 ≠ 资产写的 `m_SampleRate`** —— 同一场戏里 `sc002` 的 clip 资产写 30，
   解出来的曲线是 60。按资产的值排时间轴，那一镜就会半速播放。
2. **clip 是全长录制，时间轴只取一段** —— `cutscene_e0m2_99` 四条 clip 每条都是 3.9667 秒，
   但分别只播 0.82 秒；而且**同一条 take 会被放两次**（`sc006` 在 16.4s 和 40.98s 各一次）。
3. **镜头不一定叫 `a_cam_`** —— `cutscene_e0m2_2` 的镜头 clip 叫 `a_actor_cam_e0m2_2_002`
   （kind=actor、subject=cam）。按 kind 认镜头会把它当成"没有模型的角色"丢掉。

## 一个角色的动画分散在三处

同一个角色（短名，如 `jsspsi`）的动画在三棵不同的树下，短名是唯一的连接键：

| 来源 | 路径 | 命名 |
|---|---|---|
| 演出 | `arts/gameplay/cutscene/<演出>/animations/<分镜>/a_actor_<短名>_NN_cs_…` | 只有分镜 id，无语义 |
| 对话表情 | `gameplay/dialog/timeline/<对话>/morphanim*/<对话>_npc_chr_00NN_<短名>_<行号>` | 带 `chr` 完整 id |
| **角色自己的库** | `arts/entity/actor/<体型>/<短名>/animations/<用途>/a_actor_<短名>_…` | **有语义**：`idle_loop_additive`、`dialog_state_idle`、`dialog_virtual_single_idle_talkhands`、`cloth_ik_highres` |

短名 ↔ 角色 id 的判据是 `gamedata/characterdata/data_chr_00NN_<短名>.asset` 的存在
（**不是** CharacterTable —— 1.4.4 里 `jsspsi` 就没有这份数据资产，但她的动画一条不少）。
对话侧 token 要先剥 `npc_` 与 `chr_<数字>_` 才能跟演出侧同名。

实例（祀 = `jsspsi`，一次查询 1.9 秒）：演出 5 条（`cutscene_e11m1_3` sc020–022、
`cutscene_e11m1_4` sc002–003）+ 对话表情 239 条（分布在 5 个 dlgtl）+ 自己的库 61 条
（`dialog` 31 / `customized` 19 / `animations` 11）。

对话侧的 `morphanim/*.anim` 是 **每句台词一条的表情动画**，命名
`<timeline>_<actor>_<行号>`（actor 形如 `npc_chr_0035_liino`，直接带角色 id）；
同名的 `morphanimso/*.asset` 是它驱动的 SkeletalMorph 资产。

**这些 .anim 是变换曲线不是浮点 ctrl 值**：曲线路径是哈希化的
`path_0xC66F354B_KrsjsUH` 形式（`m_PositionCurves` 有值、`m_FloatCurves` 无），
也就是走 ctrl 骨骼那条路，能被普通的 clip 导入链路吃下。

## 规模（1.4.4）

| 通路 | 单位数 | 动画数 |
|---|---|---|
| Cutscene | 88（其中 50 个自带动画目录） | 4,263 |
| Dialog Timeline | 421 | 16,376（另有等量的 morphanimso 资产） |

数量与分类可用 CLI 零解码复现（约 2 秒）：

```
Ruri.RipperHook.CLI.exe --hook EndField_1.4.4 --cab-map <map> \
    --data endfield.story.units --data-arg channel=cutscene --query-limit 0
Ruri.RipperHook.CLI.exe --hook EndField_1.4.4 --cab-map <map> \
    --data endfield.story.clips --data-arg channel=cutscene --data-arg unit=cutscene_c17m3_1
# 按角色:963 个 actor 的索引,以及某一个的全部剧情动画(含它自己的库)
Ruri.RipperHook.CLI.exe --hook EndField_1.4.4 --cab-map <map> --data endfield.story.actors
Ruri.RipperHook.CLI.exe --hook EndField_1.4.4 --cab-map <map> \
    --data endfield.story.clips --data-arg actor=jsspsi --query-limit 0
```

🛑 **千万别为了看一眼资产就 `--load <gameRoot> --export`**：那会让 AR 去铺整个 150 GB 安装，
实测把 25 GB 内存吃满后卡死（exit 137）。要看单个资产就先用 `--cab-query` 拿到精确 CAB，
再走面板那条 `import_cabs([cab])` 的精确读取。
