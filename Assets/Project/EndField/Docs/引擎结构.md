# 引擎结构

## ECS 覆盖层：GameObject 即 Entity

MonoBehaviour 不存在，直接叫 **`Behavior`**，继承链在类型定义生成阶段有错误——
也许他们已经把 mono 后端换成 netcore 现代化版本了。

「找不到根类」错误的根本原因：它是一个 **ECS 覆盖层**，只有叶子组件和 `MonoBehaviour`(114)，
**整个抽象链被丢弃**（`Behaviour` / `Component` / `Transform` / `Renderer` / `Collider` … 约 15 个基类）。

确实平坦化了，符合 ECS：**GameObject 即 Entity 本身，不存在任何数据**。

## Mesh 的 m_CollisionMeshBaked 分支

一个垃圾设计：`m_CollisionMeshBaked` **打破了数据平坦化**，既有分支惩罚，又让类型树自动读取
读不对——必须手写 retarget。要点：

- `m_CollisionMeshOnly` / `m_CollisionMeshBaked` / `m_CollisionMeshConvex` 三个 bool 只作局部变量缓存，用于对齐流
- **`m_CompressedMesh` 只在 `!m_CollisionMeshBaked` 时才读**，这就是分支所在
- `m_MeshCompression == 4` 要归零
- 结尾还有 `m_MeshMetrics_*`、`m_StreamData`、`m_BonesPerVertex`

实现见 `Ruri-RipperHook` 里的 `[RetargetMethod(typeof(Mesh_2020_1_0_a19))] Mesh_ReadRelease`。
