# 关卡逻辑数据（MemoryPack）

## 为什么和场景数据格式不同

**美术走 FlatBuffers，关卡逻辑走 MemoryPack，两条独立管线。** 不是异常，是分工。

关卡实体数据在 `Data/Json/LevelData/<lv>/<lv>_lv_data.json`（`.json` 只是扩展名），
一个主文件 + 一批 `_sub_<名字>` 分片（按玩法模块切：`_sub_factory` / `_sub_env` /
`_sub_npc` / `_sub_world_energypoint` …）。

`MemoryPackDeSerializerRegister` 里注册了 `Beyond_Gameplay_LevelData`、
`Beyond_Gameplay_LevelInteractiveData` 等；文件头字节 = `LevelData` 的成员数，两边对得上。

## 关键类型

| 类型 | 要点 |
|---|---|
| `LevelData` | 43 个成员，**按字母序**排列。`enemies` → `enemyGroup` → **`interactives`** → `spawners` → … |
| `LevelEntityData` | 基类。`entityDataIdKey` / `entityType` / `levelLogicId` / `position` / `rotation` / `scale` |
| `LevelInteractiveData` | 继承上者，另有 `componentProperties` / `properties` / `isLocked` / `modelScale` 等 |
| `LevelEnemyData` | 也继承 `LevelEntityData` |

**没有随机访问**：要读第 20 个成员 `interactives`，必须先完整解析前 19 个。

## wire 格式

- **对象头 = 单字节成员数**；`0xFF` = null 对象
- **成员序 = 字母序，不是声明序**
- 继承：基类成员并入计数
- 字符串 = `[i32 字节数][UTF8]`
- 版本容忍：写入方成员少时只写前 N 个；反过来（wire 比 schema 多）说明 schema 不对
- **`Nullable<T>`（T 非托管）= 原始结构布局**：1 字节 has-value + 对齐填充 + 值。
  `float?` 占 8 字节（1+3+4），不是紧凑的 5 字节
- 完整规格 = `E:\Temp\RealCS\MemoryPack.Beyond\` 下的 `*ForMemoryPack.cs`
  （成员名 + 类型 + union tag 全在）⇒ **写转译器，别手写 schema**
